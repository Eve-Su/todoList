**六、Prompt 设计建议**
一期先做最小可用，不追求 fancy。

建议组装成 OpenAI 风格 messages：

1. `system`
   内容示例：

```text
你是企业AI助手。
请优先基于提供的知识片段回答。
如果知识片段不足以支持结论，请明确说明“根据当前知识库内容无法确认”。
回答尽量简洁、准确、结构清晰。
```

2. `system` 或 `user` 附加知识片段
   把检索结果拼成：

```text
知识片段1:
...

知识片段2:
...
```

3. 历史消息
   从 `recentMessages` 转成：
- `USER -> user`
- `ASSISTANT -> assistant`

4. 当前用户问题
   作为最后一条 `user`

这样好处是：
- 简单
- 可控
- 容易排查 prompt 问题

**七、异常处理策略**
这一块最好先定规则，不然主链路很容易一碰就炸。

建议这样：

1. `knowledge-service` 调用失败
- 记录 warn 日志
- `knowledgeSnippets = empty`
- 继续调 LLM

2. `LLM` 调用失败
- 抛统一业务异常，比如 `LLM_CALL_ERROR`
- controller 返回统一错误体

3. `LLM` 返回空 answer
- 判定为异常
- 不保存 assistant 空消息

4. session/message 持久化失败
- 直接失败
- 因为聊天上下文一致性比“返回一句话”更重要

**八、日志建议**
主链路建议加这些日志点：

1. 聊天开始
   记录：
- `sessionId`
- `agentCode`
- `userId`
- `traceId`

2. 知识检索结束
   记录：
- `kbCode`
- `hitCount`

3. LLM 调用结束
   记录：
- `model`
- `latencyMs`
- `answerLength`

4. 聊天完成
   记录：
- `sessionId`
- `messageCount`
- `referencesCount`

这样一条请求基本就能完整排查。
